# Проверка противоречий и ответы чата

Новые, опубликованные и содержательно изменённые статьи автоматически попадают в фоновую очередь сверки. Worker находит близкие статьи во всей базе, сравнивает правила и сохраняет цитаты. Чат использует актуальные результаты при ответе. Автосверка включена по умолчанию; для обращений к модели нужны LLM-настройки и доступный дневной бюджет.

## Автоматически после загрузки

1. Загрузите и опубликуйте статьи или сохраните правку опубликованной статьи.
2. Откройте **Админ → Противоречия**: сразу показаны найденные расхождения с двумя цитатами. Раскройте **Управление проверкой**, чтобы увидеть очередь, ход работы и ошибки. Само сохранение статьи не ждёт модели.
3. При необходимости настройте переключатель, число соседей, паузу и дневной предел в **Настройки → Проверка противоречий**. По умолчанию: 5 соседей, 5 секунд паузы, 100 вызовов в сутки UTC и максимум 2 попытки.
4. Для ранее загруженной базы проверьте оценку объёма и нажмите кнопку постановки существующих статей в очередь. Это явный запуск: старая база не начинает платную сверку просто от перезапуска приложения.

Очередь, версии и дневные расходы сохраняются в БД. Нулевой лимит или отключение приостанавливают модельные вызовы. Новые правки выполняются раньше исторического обхода. Длинные источники и неудачные проверки отмечаются отдельно; они не считаются успешно проверенными. [Устройство очереди, ограничения и массовая проверка](experiments/source-conflicts-automatic.md).

## Через интерфейс

1. Войдите администратором и откройте **Админ → Противоречия** (`/admin/source-conflicts`).
2. Раскройте **Проверить статьи вручную** и найдите близкие по теме опубликованные ответы. Отметьте от 2 до 20 статей; источник и фрагмент ответа помогают отличить одинаковые заголовки.
3. При необходимости откройте **Ограничения проверки**, задайте предел пар, вызовов модели и времени. Нажмите **Проверить выбранные статьи**.
4. Статус обновляется автоматически; можно продолжать пользоваться приложением. Задание, затраты вызовов и результаты сохраняются в БД.
5. Откройте расхождение и сверьте обе точные цитаты. Полный текст, происхождение и объяснение модели раскрываются отдельно. **Подтвердить** означает, что расхождение действительно есть, а не что один из источников верен. **Отклонить** убирает находку из проверки ответов. Решение требует пояснения и записывается с автором; его можно вернуть на проверку.
6. Исправьте исходную статью штатным редактором БЗ, если выяснен верный текст. Старые результаты станут неактуальными; их видно по переключателю **Показать устаревшие**. Новая версия автоматически попадает в очередь; при необходимости её можно проверить вручную.

По умолчанию список содержит только расхождения. В блоке **Фильтры** можно отдельно выбрать неясные сравнения или пары без расхождений; у таких пар нет статуса проверки человеком. История запусков находится в свёрнутом **Журнале проверок**.

Непроверенные и подтверждённые актуальные конфликты участвуют в проверке чата. Отклонённые, устаревшие и несовместимые с ролью посетителя не участвуют. У совместимых/неопределённых пар нет кнопок подтверждения конфликта. Ошибки и исчерпание бюджета показаны отдельно от успешно завершённой проверки; при исчерпанном бюджете нужно выбрать статьи и начать новую проверку с подходящими ограничениями.

## Что получает посетитель

Чат сопоставляет вопрос и фактически используемые источники с реестром. Если ответ опирается на спорное утверждение, посетитель получает обе цитаты, ссылки на статьи и кнопку передачи оператору. До этой проверки уверенный текст не стримится. Обычный вопрос о другом факте той же статьи не должен блокироваться лишь из-за наличия расхождения. Для этого используются слова вопроса и цитат, формы слов, числа вместе с единицами измерения.

Это консервативная эвристика применимости, а не доказанная семантическая полнота. Единичное прохождение контрольного набора не даёт оценки точности всей базы. Автоматического выбора действующего правила нет. Исторический проход охватывает каждую подходящую статью и ограниченное число её соседей; семантическая полнота не гарантируется.

## Настройка

Используется штатная модель `llm.base_url`, `llm.api_key`, `llm.model`. Сохранённые настройки БД имеют приоритет над `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Ручной запуск, обход старой базы и настройки автосверки доступны администратору; API просмотра — сотрудникам. Обычное сохранение опубликованной статьи ставит её в очередь согласно этим настройкам. Без модели запуск возвращает понятную ошибку, а не фиктивный результат.

Схема синхронизируется штатным `Database.create_all` на старте приложения: добавляются таблицы реестра и служебная версия статьи. Версии меняются транзакционно во всех текущих ORM-путях записи, независимо от успеха векторной индексации. Будущий прямой Core SQL код должен отдельно обновлять `source_version`.

Поиск пар объединяет лексическое сходство и эмбеддинги внутри выбранного пула. Без `TEI_URL` действует штатный HashEmbedder, который не даёт семантического качества. Аудит использует полные короткие тексты; длинные источники пропускаются, а не незаметно обрезаются для сравнения моделью.

## Ограничения и возобновление

API/CLI принимают до 200 явных ID; интерфейс ограничивает выбор 20 статьями. Максимум 500 пар в задании. Отдельно ограничиваются число вызовов, время всего прохода, время одного запроса и размер ответа. `attempted_calls` сохраняется **до** отправки модели и не обнуляется при возобновлении. Встроенные повторы SDK/детектора отключены. Кэш действующих пар не требует нового запроса. Ручной runner выполняет одно задание на процесс; автоматический worker защищён общей арендой в БД. Дубли вложенного задания также защищены lease.

`max_article_chars` ограничивает полный вопрос и ответ, метаданные — ещё 4000 символами JSON на источник. Поисковые `origin.phrasings` в модель не передаются. Превышения отражаются в `skipped_long_articles`. Вызовы эмбеддингов не входят в счётчик LLM; точный денежный бюджет и суммарный токен-биллинг не реализованы.

Ошибка транспорта, неправильный формат ответа или таймаут сохраняются как незавершённое задание. Ручной повтор — явное действие пользователя и расходует оставшийся бюджет; автоматическая очередь допускает не более настроенного числа попыток, учитывая дневную квоту. После остановки процесса running-job можно возобновить после истечения lease. При изменении модели/версии обработки нужен новый аудит. Завершённый ограниченный проход не означает проверку всех возможных пар или всей базы.

При разных явно названных событиях отсчёта срока detector консервативно сохраняет неопределённость. Настроенный Ollama Cloud не гарантирует нативный JSON Schema output; поэтому схема и цитаты валидируются приложением, ошибочные ответы не превращаются в находки. См. [документацию Ollama](https://docs.ollama.com/capabilities/structured-outputs).

## CLI и проверка

Команды из `backend`, с отдельной БД при параллельной разработке:

```sh
.venv/bin/python -m app.tools.source_conflicts --database-url sqlite+aiosqlite:////private/tmp/conflict-smoke.sqlite3 init-schema
.venv/bin/python -m app.tools.source_conflicts --database-url sqlite+aiosqlite:////private/tmp/conflict-smoke.sqlite3 audit --article-id ARTICLE_A --article-id ARTICLE_B --max-pairs 10 --max-calls 10
.venv/bin/python -m app.tools.source_conflicts --database-url sqlite+aiosqlite:////private/tmp/conflict-smoke.sqlite3 list --kind conflicts --outcome conflict
.venv/bin/python -m app.tools.source_conflicts --database-url sqlite+aiosqlite:////private/tmp/conflict-smoke.sqlite3 show JOB_ID
.venv/bin/python -m app.tools.source_conflicts --database-url sqlite+aiosqlite:////private/tmp/conflict-smoke.sqlite3 resume JOB_ID
```

CLI `list`/`show` открывают SQLite только для чтения и не запускают модель. JSON содержит `status`, `summary`, `next_actions`, `artifacts`. Код 0 означает успешное завершение команды, 1 — ошибку/незавершённый аудит, 2 — ошибку аргументов.

Размеченные искусственные случаи находятся в `backend/evals/source_conflicts/cases.json`. Явный запуск с настоящей настроенной моделью (до 20 случаев, один вызов на случай, без повторов):

```sh
PYTHONPATH=. .venv/bin/python evals/source_conflicts/run_live.py --output data/source-conflicts-eval.json
```

Этот запуск обращается к настроенному внешнему провайдеру. Для обычных локальных тестов используются подменённые провайдеры; их результаты нельзя выдавать за оценку модели. Фактические живые прогоны и ограничения зафиксированы в [отчёте полного флоу](experiments/source-conflicts-live-qa.md).
