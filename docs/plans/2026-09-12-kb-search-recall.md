## 1. Зачем это делается

Два жалобных сценария:

1. «Что такое УПД?» — бот говорит «в базе знаний нет информации», хотя определение в базе есть.
2. «Как выгрузить УПД?» — отвечает через раз, смотря какими словами ReAct-агент переформулирует запрос.

Это не баг агента и не недоработка коммита `46e6e0d` («выгрузить/скачать/экспорт — один синоним»). Тот коммит починил токенизацию, но на ранжирование не повлиял. Причин три, они независимы.

Цель: оба вопроса отвечаются верно и **одинаково при любой формулировке**; `confident_wrong_rate` = 0; `accuracy` на золотом наборе не ниже пола 0.53 (`backend/tests/test_confidence_golden.py:51`).

## 2. Диагноз (замеры на проде)

Индекс берёт только `status='active'` — 6151 статья из 9985 (`retrieval.py:419-421`).

### Причина 1 — синоним весит вдвое меньше буквального совпадения

`index_tokens` (`backend/app/services/retrieval.py:97-121`) **добавляет** ключ синонима рядом с буквальной основой вместо замены.

Сокращения ведут себя иначе: `_concepts()` пишет `by_word[abbreviation] = key` (`querytext.py:209`), `concept_of()` срабатывает, слово **заменяется**. Цикл `SYNONYM_GROUPS` (`querytext.py:215-218`) в `by_word` не пишет сознательно — члены группы склоняются (выгрузить/выгрузка/выгружает), точный словарный поиск их не поймал бы, в отличие от неизменяемых аббревиатур. Они идут через `concepts_in_words` (`querytext.py:244-260`), который возвращает только ключи, без позиций, и потому умеет лишь дописывать.

idf на проде (N=6151): `_download`=3.4138 (df=202), `упд`=1.5082 (df=1361), `выгруз`=4.276 (df=85), `скачат`=4.843 (df=48).

| статья | совпавшие токены | вес |
|---|---|---|
| «9.1.1 Выгрузка оферт» (не про УПД) | выгруз 4.276 + _download 3.414 | **7.69** |
| «Где можно скачать XML‑версию УПД?» (верная) | _download 3.414 + упд 1.508 | **4.92** |

Буквальное совпадение получает двойной зачёт, перефразировка — половинный.

### Причина 2 — верная статья не доходит до скоринга

Отсечка кандидатов `retrieval.candidates`=20 × `OVERFETCH`=2 = 40 на источник (`retrieval.py:694-724`). Замер для «как выгрузить упд»: BM25-ранг верной статьи **59**, векторный — **за 300**. `_assign_scores`, где живёт эффект синонима (`title_match` вырос 0.130 → 0.327), считается только по выжившим кандидатам.

Слоты съедают дубликаты: `newest_per_question` (`retrieval.py:161-169`) схлопывает одинаковые вопросы **после** `_fuse`. На проде 646 лишних дублирующих строк среди активных: «СОДЕРЖАНИЕ» ×38, «Содержание» ×28, «Таблица 1 - Перечень терминов и сокращений» ×22, «Москва» ×18.

### Причина 3 — глоссарий в архиве, замена неотвечаема

Статья `8a76f4bcff5a404c8c059cbd81f84173` «Что означает аббревиатура УПД в системе Портала поставщиков?» — `status='archived'`. Заархивировал `_archive_previous` (`ingest/pipeline.py:222-255`) при переимпорте документа с `doc_key='инструкция по работе с порталом для поставщика'`. В новой версии её место занял заголовок «Таблица 1 - Перечень терминов и сокращений» — весь глоссарий одной статьёй, определения в теле. При `TITLE_SHARE=0.75` (`retrieval.py:297,738`) определение внутри таблицы выиграть не может.

Живой прогон «что такое упд»: топ-1 = 0.6024 «Что делать, если в контракте отсутствует дата заключения…» — выше порога 0.4, агент получает 5 нерелевантных статей и по правилу 2 системного промпта честно возвращает NO_ANSWER. То есть отказ — следствие плохой выдачи, агент работает верно.

Активные статьи, где расшифровка УПД есть в теле: `be7a8f08f5c6405e9de8bdcd7dac62b3` («Что такое электронное актирование и УПД?»), `926ad5f7aab942ec882c851f88e20ed1`, и две копии «Таблица 1 - Перечень терминов и сокращений» (`3a8699c6baa2455caa4cf7caa6e0cb8d`, `b5a44aedab524642a93cab3e293fa3fd`).

## 5. Работы

### Шаг 1 — синоним заменяет основу (ядро, подтверждено симуляцией)

`backend/app/services/querytext.py`:
- В `_Concepts` (`:190-198`) добавить поле `replacing: frozenset[str]` — ключи, чьи слова вытесняются. Заполнять разрешёнными ключами `SYNONYM_GROUPS` в `_concepts()` там же, где они кладутся в `by_phrase` (`:215-218`).
- Вынести общий проход в `concept_spans(words) -> list[tuple[str, int, int]]` — `(ключ, индекс первого слова, длина)`. Тело — нынешний цикл `concepts_in_words` (`:244-260`), который теряет позиции.
- `concepts_in_words` сохранить по сигнатуре (его зовут `phrase_concepts` и тесты), выразив через `concept_spans`.

`backend/app/services/retrieval.py`, `index_tokens` (`:97-121`):
- Взять `spans = concept_spans(words)`, собрать индексы слов, накрытых спаном с ключом из `replacing`.
- В цикле по словам пропускать накрытые; остальное (`concept_of` → замена, иначе стем с фильтрами `_MIN_TOKEN_LEN`/`_STOPWORDS`) не менять.
- В конце по-прежнему дописать ключи всех спанов.
- Поправить докстроку: она сейчас прямо утверждает «Слова полной формы остаются».

Вложенные понятия (укэп/кэп/эп) — расшифровки аббревиатур, не в `replacing`, остаются аддитивными. Проверить перекрытие спана-заменителя со спаном расшифровки.

`align_concepts` (`querytext.py:277-327`): ветка `synonym_mismatch` из `46e6e0d` становится мёртвой — после замены обе стороны несут только ключ, `_spelled_out` вернёт пусто, сработает ветка `abbreviated`. Ветку убрать, её тест перецелить.

**Риск под тест.** Основа группы `экспор` (от «экспорт») через `_fits` накрывает любое слово на `экспор` с хвостом ≤7 букв — «экспортер» (компания-экспортёр), «экспортный». Сегодня такое слово хотя бы дополнительно отдавало свой стем; после замены **теряется целиком**. Добавить регрессионные тесты; при просадке на замере — убрать из группы голое существительное «экспорт», оставив «экспортировать» (основа `экспортиров` безопасна).

Тесты: `backend/tests/test_querytext.py` (`test_download_synonyms_are_one_concept` → проверка замены: `index_tokens("как выгрузить упд")` больше не содержит `выгруз`), `backend/tests/test_retrieval.py` (`test_download_synonyms_share_a_lexical_token`, `test_download_synonym_matches_title_written_with_a_different_word`).

### Шаг 2 — дубликаты не съедают слоты кандидатов

В `_fuse` (`retrieval.py:690-725`) пропускать хит, чей ключ вопроса уже занят, — переиспользовать `_same_question_key` (тот же, что у `newest_per_question`, `:161-169`). Тогда 22 копии глоссария стоят одного слота, а не двадцати двух. `newest_per_question` после `_fuse` оставить: он выбирает свежую из одинаковых, это его роль.

Дёшево, локально, усиливает шаг 1 по recall.

### Шаг 3 — мусор не ответ

`backend/app/ingest/`:
- Общий предикат «заголовок — подпись/оглавление, а не вопрос». Переиспользовать `_CAPTION` из `ingest/tables.py:30` (`^\(?\s*(рисунок|таблица|см\.|figure|table)\b`) — **вынести в общий модуль, не копировать**; добавить распознавание «СОДЕРЖАНИЕ»/«Содержание».
- Применять к `record.question` там, где собирается запись (`ingest/document.py`, `ingest/sources/pdf_figures.py`), выставляя `Provenance.kind = kbkind.REFERENCE` (`ingest/records.py:29`). `REFERENCE` описан в `kbkind.py:11-12` ровно как «полезен для рубрик, но ответом быть не может» — это он.

Цель: 782 подписи к рисункам + 66 оглавлений.

`KeywordIndex.build` не сокращать: тем же индексом ищет `search_cases` по `OPERATOR_CASE`. Отсев по kind идёт в `_fits` (`retrieval.py:518-543`), а счётчик рангов в `_fuse` растёт только на прошедших `_fits` — значит классификация сама освобождает слоты кандидатов.

**Бэкофилл 1580 уже импортированных статей на проде.** Разовый инструмент в `backend/app/tools/`, проставляющий `origin['kind']` в БД по тем же правилам. Перевекторизация не нужна: `_fits` берёт kind из `self._payloads`, которые `refresh_from_db` читает из БД, а payload Qdrant — только если индекс пуст (`retrieval.py:527-540`). Достаточно обновить БД и дождаться `refresh_from_db`.
