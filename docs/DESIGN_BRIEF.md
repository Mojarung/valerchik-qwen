# Дизайн-бриф: «Валерчик» — ИИ-поддержка Портала поставщиков

Документ для дизайнера (человека или нейросети). Описывает продукт, все страницы, блоки,
состояния и данные, которые нужно отобразить. Текущая реализация — рабочий каркас на
React 19 + Tailwind CSS v4 + иконки lucide-react; редизайн делается поверх неё
(токены в `frontend/src/styles/global.css`, компоненты в `frontend/src/pages/**`).

## 1. Что за продукт

Веб-сервис автоматизации службы поддержки **Портала поставщиков** (zakupki.mos.ru —
госзакупки Москвы: поставщики, котировочные сессии, контракты, электронные подписи).

ИИ-агент отвечает на вопросы пользователей по базе знаний, показывает **источники ответа
с подсветкой** и **уровень уверенности**. Если ответа нет — честно признаётся и передаёт
обращение живому оператору нужной линии. Нецензурная лексика автоматически завершает диалог.
Администратор управляет базой знаний, настройками и смотрит аналитику качества.

**Три роли → три рабочих пространства:**
1. **Пользователь** (поставщик, часто нетехнический человек 30–60 лет) — только чат.
2. **Оператор поддержки** — очередь обращений + чат + ИИ-подсказки.
3. **Администратор/руководитель** — база знаний, настройки, дашборды.

## 2. Брендинг и характер

- Имя: **Валерчик** — так зовут и сервис, и маскота.
- Маскот: анимированная SVG-крыска в гарнитуре оператора, 6 состояний
  (idle — зрачки следят за курсором / thinking — перебирает карточки картотеки / speaking /
  sorry / alert / happy). Уже реализован (`frontend/src/components/Mascot.tsx`), встраивается
  в новый дизайн как есть или перерисовывается по промпту из `docs/MASCOT.md`.
- Акцентный цвет: красный в духе mos.ru (`#D6001C`-семейство). Сейчас: light-тема,
  нейтральные поверхности, красный акцент. Направление редизайна — на вкус дизайнера,
  но это **государственный сервис**: доверие, спокойствие, никакой игривости сверх маскота.
- Тон текстов: вежливый, деловой, на «вы».

## 3. Технические рамки

- React 19 SPA, Tailwind v4 (`@theme` токены), lucide-react (SVG-иконки, MIT), recharts (графики).
- Адаптив: 320 / 375 / 768 / 1024 / 1440 / 1920. Мобильный приоритет — чат; оператор и
  админка — desktop-first, но должны быть юзабельны на планшете.
- Тёмная тема: опционально, если делается — обе темы осознанно.
- Доступность: контраст WCAG AA, focus-visible на всём интерактиве, `prefers-reduced-motion`.
- Живые обновления по WebSocket — интерфейс должен показывать «жизнь»: стриминг текста,
  typing-индикаторы, всплытие новых тикетов без перезагрузки.

## 4. Карта страниц

### 4.1 `/` — Чат пользователя (главная, публичная)

Назначение: задать вопрос и получить ответ за секунды.

Блоки:
- **Шапка диалога**: маскот (реагирует на события), статус («отвечает мгновенно, 24/7» /
  «думает…» / «диалог завершён»), кнопка «Новый диалог».
- **Лента сообщений**: пузыри пользователь (справа) / ассистент (слева, Markdown) /
  оператор (слева, с бейджем «Оператор») / системные (по центру, пилюли).
- **Под ответом ассистента**: чипы-источники «вопрос статьи + % релевантности» (кликабельны →
  модалка источника) + подпись «уверенность N%».
- **Модалка источника**: заголовок статьи, категория, % релевантности, текст статьи
  с **подсветкой предложений**, из которых собран ответ; пояснение внизу.
- **Стриминг**: ответ печатается кусками с курсором-морганием.
- **Чипсы-подсказки** (стартовое состояние): 4–8 популярных вопросов.
- **Автодополнение** при вводе: выпадающий список подсказок из БЗ.
- **Композер**: textarea (Enter — отправить), кнопка микрофона (голосовой ввод, состояние
  записи — пульсация), кнопка отправки.
- **Баннер эскалации**: «Обращение передано на линию N, оператор подключится» (жёлтый).
- **Карточка оценки** (после закрытия диалога): 5 звёзд + необязательный комментарий.
- **Состояние нарушения**: системное сообщение «Обращение завершено за нарушение правил»,
  композер заблокирован, ссылка «Начать новый».

События реального времени: message, assistant_chunk (стриминг), typing, escalated,
session_closed.

### 4.2 `/login` — Вход для сотрудников

Карточка по центру: маскот, логин/пароль, ошибки, подсказка демо-доступов. После входа —
редирект по роли.

### 4.3 `/operator` — Рабочее место оператора (роль operator/admin)

Трёхколоночный layout (desktop) / стек с навигацией назад (mobile):

- **Колонка 1 — Очередь**: фильтры «Очередь/Все», карточки обращений: бейдж линии (Л1/Л2/Л3),
  статус (ждёт оператора / в работе / с ботом / решён / нарушение), время, превью последнего
  сообщения. Новые тикеты появляются live + счётчик.
- **Колонка 2 — Чат**: история (включая ответы ИИ до эскалации), «посетитель печатает: …»
  (live-превью текста!), быстрые шаблоны-чипсы над композером, композер. Действия в шапке:
  «Взять в работу» / «В базу знаний» / «Завершить».
- **Колонка 3 — Подсказки из базы знаний**: (а) авто-подсказки к последнему сообщению
  пользователя — карточки статей БЗ со скором и кнопкой «Вставить в ответ»;
  (б) ручной поиск по базе знаний.
- **Модалка «В базу знаний»**: вопрос+ответ → черновик статьи (публикует админ).

### 4.4 `/admin` — Админка (роль admin), сайдбар + 5 разделов

**Дашборд**: 4 стат-карточки (диалоги, % автоответов ИИ, средняя оценка, нарушения),
графики за 14 дней (диалоги+эскалации; средняя оценка), эскалации по линиям (bar),
блок базы знаний (статей/пробелов) + кнопки выгрузок CSV/JSON.

**База знаний**: поиск + фильтр статуса (активна/черновик/архив), таблица (вопрос+превью
ответа, категория, линия, статус-бейдж, источник: seed/manual/operator/gap/import),
пагинация, модалка-редактор (вопрос, ответ, категория, линия, статус, ключевые слова),
импорт JSON, «Переиндексировать». Ключевой месседж UI: «сохранил → сразу ищется».

**Настройки**: группы (Чат, ReAct-агент, LLM, Guardrails, Поиск, Линии, Rate limit, Голос,
Обратная связь); поля по типу значения (строка/число/toggle/список/JSON), изменённые
подсвечены, плавающая кнопка «Применить N изменений без перезапуска», секреты маскируются.

**Отзывы и качество**: кнопка «Сформировать отчёт», сводка (4 карточки), блок
«Содержательное заключение» (абзац текста — главный артефакт для руководителя),
таблица специалистов от слабых к сильным (ИИ — тоже специалист; красным <3.5, зелёным ≥4.5),
кластеры системных проблем (размер, ключевые слова, типичная цитата), лента последних отзывов.

**Пробелы БЗ**: пояснение механики самообучения, список вопросов без ответа (текст, ×N повторов,
лучший скор, дата), действия: «Создать статью» (модалка: ответ+категория+линия → публикация)
и «Отклонить». Пустое состояние: «Открытых пробелов нет».

### 4.5 Служебные
`/dbadmin` (SQLAdmin, вне SPA), `/api/docs` (Swagger) — дизайн не нужен.

## 5. Компонентная система (минимум)

Кнопки (primary/ghost/icon), инпуты + textarea + select, чип (подсказка/источник/шаблон),
бейджи статусов и линий, карточка, модалка, таблица с пагинацией, toggle, звёзды оценки,
toast/inline-уведомления, стат-карточка, пустые состояния, скелетоны/спиннеры, маскот.

## 6. Данные, которые обязан показывать дизайн

- Сообщение ассистента: `content` (Markdown!), `citations[] {question, score 0..1}`,
  `meta.confidence`, `meta.answered`, `meta.escalated`, `meta.tool_trace` (можно спрятать
  в «подробности» — след ReAct-агента: какие инструменты вызваны).
- Статус диалога: active / waiting_operator / operator_active / resolved / closed_violation.
- Линии поддержки: 1 «Общие вопросы», 2 «Техническая поддержка», 3 «Закупочные процедуры»
  (названия приходят из настроек — не хардкодить).
- Оценка 1–5, сентимент −1..1.

## 7. Чего не делать

- Не прятать «уверенность» и источники — это ключевая честность продукта.
- Не делать тёмный дашборд «как у крипты» — это госсервис.
- Не заменять маскота стоковым роботом.
- Не ломать live-паттерны: стриминг, typing, всплытие тикетов — должны быть видимы.
