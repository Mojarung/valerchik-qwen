# Полный флоу противоречий: реализация и живая проверка

Этот отчёт описывает предыдущий этап ручной сверки. Автозапуск после загрузки и последующий массовый проход описаны в [актуальном отчёте](source-conflicts-automatic.md).

Дата: 12 сентября 2026. Ветка: `codex/source-conflicts-audit`, продолжение коммита `a82e2ad`. Работа и проверки проведены в отдельном клоне. Исходное рабочее дерево параллельной задачи, его БД и запущенные сервисы не изменялись. Существующий TEI использовался только для inference.

## Что теперь работает

Администратор выбирает статьи в `/admin/source-conflicts`, запускает ограниченный аудит, видит прогресс и открывает результат с двумя точными цитатами, полными текстами и происхождением. Подтверждение, отклонение и возврат на проверку сохраняют автора, время и пояснение. Изменение/удаление/архивация статьи делает результат неактуальным.

Перед отправкой дословного или сгенерированного ответа чат проверяет актуальные конфликты используемых источников. Применимый конфликт заменяет уверенный ответ двумя цитатами и предложением оператора. Отклонённые и устаревшие находки не участвуют. Несовместимые с ролью источники не раскрываются. Уведомление о конфликте и окно статьи не показывают вводящие в заблуждение «уверенность 0%»/«релевантность 0%».

ECC: `orch-add-feature` / `orch-pipeline`, `eval-harness`, `browser-qa`; реализация с регрессионными тестами, независимые ревью кода и безопасности, настоящие HTTP-запросы и браузерный прогон.

## Изолированный стенд и настоящая модель

Для QA импортированы тексты и основные метаданные 6151 активной статьи из локального снимка `retrieval-implementation-20260912-1524`, восстановлен отдельный MemoryStore из 9613 векторов. SQLite, индекс, окружение, frontend build и порт 18880 принадлежат этому клону. Изображения не копировались; это не полная реплика production.

Использована настроенная облачная модель Ollama (`https://ollama.com/v1`). Пользователь явно разрешил передачу вопросов и выбранных статей. Полная база провайдеру не выгружалась. Ключи, локальная БД, журналы и сырые ответы хранятся только в игнорируемом `backend/data/live-qa`; в Git их нет.

## Аудит и жизненный цикл

- Реальная пара про срок оферты: финальное задание `1e2c2eb5ff834b0d9d9a1593f78b552c`, 2 статьи, 1 пара, 1 вызов модели, `done`, 1 конфликт. Результат `1ad87b2e417c4dea92528952ff601aba`.
- Через браузер выбраны две статьи с одинаковым вопросом о сроке заявки СТЕ; запуск завершился, результат `compatible`. Источник и превью позволяют различить одинаковые заголовки.
- Настоящие PATCH-запросы: `confirmed` → предупреждение, `dismissed` → обычный ответ, `unreviewed` → предупреждение.
- Через API редактора только в QA-копии изменено 12 месяцев на 3. Старый результат стал `stale`, попытка подтвердить его вернула 409. После исправления сбоя пропуска поиска чат ответил «3 месяца» по источникам.
- Исходная статья восстановлена в QA-копии; новый аудит снова обнаружил 12/3 месяца. Стенд оставлен в состоянии, позволяющем повторить демонстрацию конфликта.
- В браузере открыты обе статьи с подсветкой, сохранено решение администратора, нажата передача оператору. Чат перешёл в состояние ожидания специалиста линии 3; сохранение состояния после перезагрузки проверено.
- После финальной сборки: новый текст уведомления, отсутствие ложных процентов в сообщении и модальном окне; при узком viewport 500 px горизонтального переполнения не было. Ошибок/предупреждений консоли после перезагрузки чата нет, проверенные HTTP-запросы завершились 200.

## Что исправлено по фактическим сбоям

1. Модель возвращала описания вместо enum-значений: инструкции перечисляют точные значения, schema и цитаты проверяются локально. Некорректный ответ остаётся ошибкой задания, а не ложной находкой.
2. Разные точки отсчёта одинакового срока ошибочно признавались совместимостью/конфликтом. Узкая защита для явно указанных разных событий сохраняет `uncertain`, включая случай `material=no`.
3. Сопоставление цитат по одному числу путало 12 дней и 12 месяцев. Теперь учитываются и единицы.
4. Одного промпта оказалось недостаточно против выдуманной расшифровки УКЭП. Добавлено ограниченное удаление неподтверждённых расшифровок в сгенерированном ответе; исходные тексты не меняются, подтверждённые расшифровки и обычные скобки сохраняются. Ревью закрыло отдельную регрессию границы слова с дефисом.
5. Модель иногда отвечала `NO_ANSWER`, не вызвав поиск. Валидатор требует `search_kb` перед итогом, кроме существующих сценариев внешнего инструмента/оператора. Один корректирующий повтор укладывается в текущие ограничения агента; скрытые повторы detector аудита не добавлены.
6. Интерфейс показывал служебные нулевые scores как пользовательскую уверенность; для конфликтов заменено осмысленным уведомлением, включая окно источника.

## Оценка detector настоящей моделью

В `backend/evals/source_conflicts/cases.json` зафиксированы 10 искусственных размеченных случаев: прямое расхождение, перефразирование, разные формы/периоды, единицы, числа в скриншотах, явное исключение, инструкция внутри источника, разные точки отсчёта и разные факты. Runner делает ровно один вызов на случай и сохраняет все исходы, включая ошибки.

v3 и v4 дали 9/10 на первых попытках, но ошиблись на точках отсчёта. v5 дал **9/10 на первых попытках**: точки отсчёта исправлены, однако случай явного исключения завершился `UnexpectedModelBehavior`. Один отдельный явный повтор этого случая дал ожидаемую совместимость. Нельзя представлять результат как 10/10 с первой попытки. Последующее уточнение локальной защиты для `material=no` проверено регрессионными тестами; весь модельный набор после него повторно не запускался.

Это малый инженерный набор, использованный при доработке, не независимая оценка качества. Сбой формата у реального провайдера остаётся возможным и отображается как незавершённая проверка с явным возобновлением/новым бюджетом.

## Практические границы

Проверяется выбранный пул, не вся база. Применимость конфликта к вопросу определяется эвристикой слов, форм и чисел с единицами: возможны пропуски при сложном перефразировании. При недоступности реестра дольше одной секунды сохраняется существующий ответный путь с меткой `source_conflict_check=unavailable`; это не режим полного запрета ответов при сбое. Аудит не выбирает юридически действующее правило. Нагрузочная проверка, deployment и проверка production не выполнялись.

Запуск и ограничения описаны в [инструкции](../SOURCE_CONFLICTS.md). Локальный стенд этого сеанса: `http://127.0.0.1:18880`, админ-раздел `/admin/source-conflicts`.
