## Объём

Этапы 1–2 из [плана адаптации](source-conflicts-adaptation-plan.md): версии источников, реестр результатов, ограниченный ручной аудит, сохранённый прогресс и просмотр через CLI. Операторский веб-интерфейс, решения о действующем правиле, автоматическое расписание и влияние на чат относятся к следующим итерациям.

## Харнесс ECC

Применён `orch-add-feature` / `orch-pipeline`: план → тесты до реализации → реализация → независимое ревью кода и безопасности → проверки → коммит. План и коммит заранее разрешены пользователем. Размер изменения — large: новые таблицы, жизненный цикл данных и внешний вызов модели.

Исполнители используют роли ECC `planner` и `tdd-guide`; финальную проверку выполняют роли `code-reviewer` и `security-reviewer`. Реальное семантическое качество detector не выводится из результатов тестов с подменённой моделью.

## Проверки

До реализации прошли 32 существующих теста API базы знаний, импорта и времени. Новые сценарии проходили цикл red → green.

Итоговый полный прогон после исправлений ревью: **1310 passed, 1 skipped**, покрытие **91,66%** при пороге 80%. `ruff check app tests`, `ruff format --check app tests`, `mypy app` (148 модулей) и `git diff --check` прошли. Сервисы модели и основная база не использовались; фронтенд и CI отдельно не запускались.

Независимое перекрёстное ревью ECC охватило чужие файлы каждого исполнителя. Найдены и исправлены устаревшее чтение бюджета перед захватом задания, отсутствие предела метаданных LLM-запроса и зависимость теста CLI от случайного порядка идентификаторов снимков. Проверки воспроизводят конкурентное возобновление, HTTP 429/503 без скрытых повторов, точность цитат, замену документа при отказе векторного индекса, SQLite persistence/cache и команды CLI.

Повторное ревью безопасности подтвердило закрытие обоих замечаний; открытых блокеров ревью нет.

Реальный CLI `init-schema` → `list` проверен на отдельной временной SQLite без пользователей, модели и фоновых сервисов. Точность обнаружения противоречий реальной моделью на нашей базе пока не измерена. Следующий продуктовый этап — размеченная проверка качества, затем операторский интерфейс и интеграция с чатом по плану.

Метаданные каждого источника (включая происхождение и категорию) ограничены 4000 символами сериализованного JSON; поисковые `origin.phrasings` в модель не передаются. Превышение этого лимита, как и `max_article_chars` для полного вопроса и ответа, учитывается в `skipped_long_articles`: источник пропускается целиком без платного сравнения. Detector дополнительно проверяет эти границы до запроса модели.
