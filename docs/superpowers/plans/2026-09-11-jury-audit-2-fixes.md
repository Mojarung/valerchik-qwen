## Общие ограничения

- Готовность пункта = локальные гейты зелёные **и** зелёный прогон CI для запушенного SHA
  (`gh run list --branch main`), а не одни локальные команды.
- Гейты: backend `ruff check`, `ruff format --check`, `mypy`, `pytest --cov`; frontend
  `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run a11y`;
  расширение `npm test`, `npm run lint`; сервисы `uvx ruff@0.16 check/format --check`.
- UI-правки проверяются скриншотами 1440 и 390 в обеих темах и замером контраста/кегля
  по отрисованной странице (инструмент с контролем 4.54 / 21.00).
- Живые проверки — lite-стенд на изолированной `DATA_DIR`, не на `backend/data`.
- Коммиты — Conventional Commits, без строк атрибуции.

## Пункты (порядок исполнения)

### 1. Оператор видит историю и подсказки при открытии обращения (P0)
- Backend: `GET /api/operator/sessions/{id}/messages` и `GET /api/operator/sessions/{id}/suggestions`

- Тесты: сотрудник читает историю; гость без входа — 401; неизвестный диалог — 404; подсказки
  по последнему вопросу; vitest — страница оператора ходит в операторский эндпоинт и показывает
  ошибку при отказе.
- Приёмка: живой сценарий «гость → эскалация → оператор открывает» показывает переписку.
- **Готово:** `cef4bf2`. Попутно: SPA-фолбэк отдавал `index.html` с кодом 200 на неизвестный
  `/api/...` — теперь 404 (`39885b7`). CI: backend, frontend, расширение, каталог, BPMN зелёные;

### 3. Честная уверенность (P1)
- Показываемая уверенность и % источника перестают быть долей совпавших слов: неверная тема
  при полном лексическом совпадении не получает 100 %.
- Проверка — золотой набор (60 вопросов) до/после: точность топ-1 не падает, доля уверенных
  ошибок падает; регресс-тест на пару «подписать контракт ЭП → справка об опыте».
- **Готово:** `a58bf84`, CI 34542208845 зелёный. Уверенность = 0.75·совпадение с вопросом статьи
  + 0.25·совпадение со статьёй; уверенные ошибки 10 % → 0, точность первого места 0.70 → 0.75.
  Попутно: уточнение срабатывало на шуме триграмм — тесты переведены на настоящую
  двусмысленность; источник с нулевой оценкой не показывается.

### 4. Время с часовым поясом (P1)
- Тип столбца `UTCDateTime`: значение из SQLite возвращается с `tzinfo=UTC`, API отдаёт ISO
  со смещением; локальные «пришить UTC» хелперы становятся ненужными.
- Тест: время из lite-базы в ответе API содержит смещение.
- **Готово:** `96f131b`, CI 12/12 зелёный. В очереди оператора 02:29 при московских 02:29.
