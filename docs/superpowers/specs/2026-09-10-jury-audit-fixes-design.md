# Закрытие находок жюри: дизайн решений

Дата: 2026-09-10. Исходник: жюри-оценка проекта в сессии 10.09 (дизайн 7/10, код 6/10).
Цель: 10/10 по каждому критерию той оценки. Порядок работ повторяет порядок находок жюри.

## 0. Принятые решения (допущения, которые не спрашивали у заказчика)

1. **Аутентификация сотрудников переезжает на httpOnly-куку.** JWT больше не попадает в JS:
   `/api/auth/login` ставит куку `valerchik_auth` (HttpOnly, SameSite=Lax, Secure при https,
   Path=/, срок = TOKEN_TTL) и по-прежнему возвращает `token` в теле для неинтерактивных клиентов
   (mcp-server, тесты, curl). Bearer-заголовок остаётся рабочим. Токен в query-строке не
   принимается нигде (`?token=` удалён). Операторский WebSocket читает куку. Защита от CSRF:
   запрос, аутентифицированный кукой, при методе не из {GET, HEAD, OPTIONS} обязан нести заголовок
   `X-Requested-With: valerchik`; WebSocket с кукой обязан иметь `Origin` того же хоста или из
   `ALLOWED_ORIGINS`. Появляются `GET /api/auth/me` и `POST /api/auth/logout`.
2. **`?api=` в SPA работает только внутри расширения** (origin `chrome-extension:` / `moz-extension:`).
   На обычном сайте параметр игнорируется.
3. **Секреты и пароли по умолчанию.** В режиме `full` пустой или дефолтный `APP_SECRET`,
   `ADMIN_PASSWORD`, `OPERATOR_PASSWORD`, `POSTGRES_PASSWORD` останавливают старт с понятным
   сообщением. В `lite` секрет генерируется один раз и хранится в `DATA_DIR/.app-secret`;
   демо-пароли `admin12345` / `operator12345` остаются только в lite (это режим демо и тестов).
   `start.ps1` / `start.sh` при создании `.env` генерируют случайные значения и печатают их.
4. **CORS** закрывается: список `ALLOWED_ORIGINS` (пусто = только свой origin) плюс regex
   `^(chrome|moz)-extension://` для расширения. Без credentials.
5. **Лимит на `/api/auth/login`**: 10 попыток в минуту на IP (`rate_limit.login_per_minute`).
   IP берётся из `X-Forwarded-For` только при `TRUST_PROXY=1` (в compose стоит: API за nginx).
6. **Расширение**: переходы только на origin текущей страницы портала и только https; состояние
   в sessionStorage хранит `guideId` и номер шага, сами шаги перечитываются с сервера через
   background; postMessage от родителя принимается только с origin из списка портала, ответ
   уходит на этот же origin, а не на `*`; текст шага никогда не берётся из `value` поля ввода.
7. **Повторный импорт того же файла** не плодит статьи: у задачи импорта появляется `sha256`
   содержимого; при совпадении hash + title статьи прошлой задачи архивируются и заменяются
   новыми (версионирование), количество активных статей не растёт. Заголовок задачи из multipart
   проверяется на mojibake (latin-1 ↔ cp1251) и восстанавливается.
8. **Настройки**: у каждого ключа появляется человеческое название (`label`); ключ остаётся
   вторичной подписью. Каждое поле связано с `<label>`, каждый тумблер имеет имя.
9. **Форматирование и проверки**: `ruff format` применяется ко всему Python-коду один раз (отдельный
   коммит) и проверяется в CI; включаются `BLE`, `RUF100`, `ANN` для публичных функций; появляется
   `mypy` (нестрогий, но ноль ошибок); во фронтенде и расширении появляется ESLint 9 с
   `react-hooks`, `jsx-a11y`, `react/button-has-type`; tsconfig получает
   `noUncheckedIndexedAccess`, `noUnusedParameters`, `noFallthroughCasesInSwitch`.
10. **Порты**: lite-режим везде на 8090, чтобы совпадать с расширением и nginx.
11. **Шрифт Inter** поставляется с приложением (`@fontsource-variable/inter`), а не ожидается на машине.
12. **Пружинные hover-масштабы** на кнопках убираются (госсервис), остаются лёгкий подъём и цвет;
    маскот анимации сохраняет.

## 1. Контракты между частями (для параллельной работы)

### Backend ⇄ Frontend: аутентификация
- `POST /api/auth/login` `{username, password}` → 200 `{token, role, display_name, user_id}` +
  `Set-Cookie: valerchik_auth=<jwt>; HttpOnly; SameSite=Lax; Path=/; Max-Age=43200[; Secure]`.
  429 при превышении лимита, 401 при неверных данных.
- `GET /api/auth/me` → 200 `{role, display_name, user_id, username}` или 401.
- `POST /api/auth/logout` → 204, кука удаляется. Требует `X-Requested-With: valerchik`.
- Любой изменяющий запрос (POST/PUT/PATCH/DELETE) с кукой без `X-Requested-With: valerchik` → 403
  `{"detail": "Запрос без подтверждения происхождения"}`. Bearer-запросы заголовок не требуют.
- `GET /ws/operator` — без query-параметров; кука + `Origin` того же хоста. Код закрытия 4401 при
  отсутствии/невалидности, 4403 при чужом Origin.
- Выгрузки `/api/admin/export/*` — GET с кукой (без заголовков).

### Backend ⇄ Frontend: настройки
- `GET /api/admin/settings` элемент: `{key, value, category, label, description, secret}`.
  `label` — человеческое название (обязательно, непустое), `secret: bool` — значение маскировано.

### Frontend: события WebSocket (размеченное объединение)
Файл `frontend/src/lib/wsEvents.ts` создаётся подготовительной задачей, обе страницы используют его.

### Extension ⇄ Backend: сценарии
- Расширение запрашивает сценарий по id через background: `GET {server}/api/guides/{id}` → 200
  `{id, title, steps: [...]}` или 404. Это существующий публичный эндпоинт (проверить в
  `backend/app/routers/guides.py`; если есть только список — добавить `GET /api/guides/{guide_id}`).

## 2. Что НЕ делаем
- Не меняем схему БД разрушительно (только добавляем колонки: `ingest_jobs.content_sha256`).
- Не переводим анонимный чат на аккаунты: владение диалогом остаётся HMAC-подписью.
- Не добавляем виртуализацию списков: ни один список не превышает 100 строк на странице.

## 3. Критерии приёмки (по тем же критериям жюри)
- Безопасность: ни одного токена в localStorage/query; тесты на CSRF-заголовок, на отказ токену в
  query, на лимит логина, на fail-fast секрета; расширение не переходит на чужой origin (юнит-тест).
- Доступность: `aria-live` в чате с первого рендера; все модалки: Escape, ловушка фокуса, возврат
  фокуса, `aria-modal`; на каждой странице `h1`; нет полей без label и кнопок без имени
  (проверка скриптом из аудита даёт нули); skip-link.
- Архитектура: роутеры не обращаются к `session_factory` (grep = 0); у каждой ручки `response_model`;
  в `ChatService` нет `*args, **kwargs`; ни один tsx-файл не длиннее 400 строк.
- Инструменты: `ruff check`, `ruff format --check`, `mypy`, `tsc`, `eslint` (frontend + extension) —
  все зелёные локально и в CI.
- Тесты: backend ≥ прежних 498 + новые; расширение и mcp-серверы имеют тесты, идущие в CI.
- Документация: числа тестов и порты совпадают с кодом; EXTENSION.md описывает сборку виджета.
