# Приём произвольных данных и дословный ответ

Дизайн от 2026-09-09. Готовим систему к хакатону 11–13 сентября: данные организаторов
увидим только на старте, состав неизвестен.

## Задача

Кейс хакатона закрыт кодом почти целиком: автоконсультации, честный отказ, мат, линии
поддержки, аналитика отзывов, веб-интерфейс, масштабирование, BPMN. Не закрыто одно —
**приём чужих данных**. В пятницу вечером выдадут архив, и узкими местами станут:

1. **Разведки нет.** Понять, что внутри архива, нечем: ни списка форматов, ни оценки,
   что из этого мы вообще умеем читать.
2. **Импорт умеет ровно один сценарий.** `ingest_document` — одна развилка: похоже на
   таблицу «вопрос — ответ» → прямой импорт, иначе → нарезка по заголовкам. Названия
   колонок захардкожены (`вопрос/заголовок/тема/название/проблема/question/title`).
   Excel с двумя листами, JSON-дамп, колонка «Текст обращения» — правка файла на 728
   строк руками, под таймером.
3. **Данные не-БЗ грузить некуда.** Оценка специалистов по отзывам работает на наших
   синтетических данных; единственная ручка импорта `/api/kb/import` принимает статьи.
   Реальную выгрузку отзывов или лог обращений принять нечем.
4. **Ответ всегда переписывает LLM.** `run_support_agent` генерирует текст даже когда
   верхняя статья — готовая авторская пара «вопрос — ответ». Требование заказчика —
   отвечать так, как написано в файле.
5. **Картинки приезжают единственным путём:** docling выдрал из PDF, привязали по
   авторской нумерации «Рисунок 26». Картинка как таковой ответ (скриншот вместо
   текста) сейчас отсеется как мусорный кусок.

Отдельно — скорость правок: `ChatService` 1019 строк, `handle_user_message` 170 строк
подряд. Команда 3–5 человек, любая фича диалога идёт в этот файл.

## Цели

- Новый формат входных данных подключается новым файлом на ~40 строк, без правки чужого.
- Выданный архив осматривается одной командой до всякого импорта.
- Ответ на вопрос, дословно совпадающий с авторским, отдаётся как написано в файле.
- Картинка — полноценный ответ, из любого источника, а не только из PDF.
- Отзывы и логи обращений импортируются наравне со статьями.
- Правки диалога перестают конфликтовать в одном файле.

## Не цели

- Поиск и эмбеддинги не трогаем: работают, метрики померены.
- Фронтенд не переписываем.
- Новых таблиц не заводим: провенанс — одно JSON-поле в `kb_articles`.
- Схему ответа API не ломаем: расширяем, не переименовываем.

## Устройство

### 1. Запись — промежуточный формат

Сейчас парсинг и запись в БД перемешаны: `ingest_document` режет текст, ходит к LLM за
формулировками и сам пишет статьи. Разделяем: **источник отдаёт записи, конвейер их
сохраняет.**

```python
# app/ingest/records.py
@dataclass(slots=True)
class Provenance:
    file: str                 # имя исходного файла
    locator: str = ""         # «лист 2, строка 145», «стр. 7», «$.items[3]»
    source_name: str = ""     # какой источник разобрал
    authored: bool = False    # текст написан человеком, а не собран нами

@dataclass(slots=True)
class ArticleRecord:
    question: str
    answer: str
    category: str = ""
    line: int | None = None
    audience: str = "all"
    keywords: list[str] = field(default_factory=list)
    images: list[ImageRef] = field(default_factory=list)
    origin: Provenance = field(default_factory=Provenance)

@dataclass(slots=True)
class FeedbackRecord:      # → таблица feedback
    rating: int
    comment: str
    operator: str = ""
    created_at: datetime | None = None
    origin: Provenance = field(default_factory=Provenance)

@dataclass(slots=True)
class DialogRecord:        # → chat_sessions + messages
    messages: list[tuple[str, str]]   # (role, content)
    line: int | None = None
    resolved: bool | None = None
    origin: Provenance = field(default_factory=Provenance)

@dataclass(slots=True)
class AssetRecord:         # картинка/файл
    data: bytes
    caption: str = ""
    anchor: dict = field(default_factory=dict)   # {figure: "26", page: 7, ref: "screens/a.png"}
    origin: Provenance = field(default_factory=Provenance)
```

`authored` — ключевое поле. Оно отделяет авторский текст (пара из выгрузки QA, готовый
ответ оператора) от собранного нами (кусок методички, к которому LLM придумала вопрос).
Дословный ответ разрешён только для `authored`.

Провенанс кладётся в новое JSON-поле `KBArticle.origin`; существующее `source` остаётся
как есть (`seed|manual|operator|gap|import`) — его читают админка и выгрузки.

Импортированные диалоги пишутся в те же таблицы, но с `channel="import"`: иначе чужая
выгрузка на тысячу обращений подменит собой статистику дашборда и рейтинг операторов.
Аналитика и метрики фильтруют этот канал; обучение классификатора линий — нет, ему
чужие диалоги как раз полезны.

### 2. Реестр источников

```python
# app/ingest/sources/base.py
class Source(Protocol):
    name: str
    async def sniff(self, blob: FileBlob) -> float:      # 0..1, уверенность
    async def parse(self, blob: FileBlob, ctx: IngestContext) -> AsyncIterator[Record]:
```

`FileBlob` — имя, байты, распознанная кодировка, ленивый `text` (markitdown), ленивый
`tables` (для табличных форматов). Ленивый, чтобы `sniff` десяти источников не
конвертировал файл десять раз.

Реестр (`app/ingest/registry.py`) опрашивает все источники, сортирует по уверенности,
берёт лучший; если тот бросил `SourceMismatch` — следующий; последним в очереди всегда
стоит `llm_fallback`. Регистрация — декоратором, без списка в центральном файле:

```python
@register
class QaTableSource:
    name = "qa_table"
```

Стартовый набор (перенос существующей логики, не переписывание):

| Источник | Что берёт | Откуда логика |
|---|---|---|
| `qa_table` | таблица «вопрос — ответ» в markdown/CSV | `parse_article_table` |
| `spreadsheet` | Excel полистно, каждый лист — отдельный кандидат | новый, поверх markitdown |
| `json_records` | JSON/JSONL массив объектов | новый |
| `document` | методичка: нарезка по заголовкам | `split_sections` + `generate_question` |
| `pdf_figures` | PDF с иллюстрациями через docling | `extract_document` + `store_pictures` |
| `image_folder` | папка картинок, подписи из имён и соседнего текста | новый |
| `llm_fallback` | всё остальное: LLM размечает по схеме записи | новый |

**Распознавание колонок** переезжает с фиксированного списка имён на два признака,
имя — лишь первый: (1) синонимы заголовка, (2) содержимое — колонка, где больше
половины непустых ячеек кончаются «?» и короче 200 символов, это вопрос; самая длинная
текстовая колонка рядом — ответ. Так переживаем «Текст обращения» и «Решение».

### 3. Картинки как первоклассный ответ

Общий слой поверх существующего хранилища (`adapters/storage.py`, том или S3 — оба уже
работают):

- любой источник может отдать `AssetRecord`;
- привязка к записи по убыванию надёжности: **явная ссылка** в структуре (колонка
  «скриншот», путь в JSON) → **авторская нумерация** («Рисунок 26», нынешний
  `attach_images`) → **соседство** в документе;
- **ответ-картинка легален**: `_is_junk` перестаёт отбрасывать запись с пустым текстом,
  если у неё есть картинка. Сегодня такая запись отсеивается как мусор.

Схема `KBArticle.images` (`[{url, caption, page, figure}]`) не меняется — расширяем
только пути наполнения.

### 4. Дословный ответ

Новый детерминированный шаг в тракте ответа, до агента:

```
верхняя статья .origin.authored
  и косинус(вопрос статьи, вопрос пользователя) ≥ answer.verbatim_similarity
  и score ≥ answer.verbatim_score
     → отдаём answer статьи как есть, вместе с картинками, tool_trace = ["verbatim"]
иначе → нынешний путь через run_support_agent
```

Пороги и тумблер `answer.verbatim_enabled` — в `dynamic_settings`, правятся из админки
на лету, как остальные настройки. Уверенность у такого ответа — score поиска, честный
отказ и эскалация работают как раньше.

Почему отдельным шагом, а не правилом в промпте: дословность не должна зависеть от
модели. Так она работает и в mock-режиме — то есть на защите без интернета.

Для не-дословного пути промпт агента получает правило цитировать формулировки статьи, а
не пересказывать своими словами.

### 5. Разведчик данных

```
uv run python -m app.tools.recon <папка|архив> [--json] [--dry-run]
```

Отчёт: файлы и размеры, распознанная кодировка, какой источник берётся и с какой
уверенностью, сколько записей каждого вида получится, три примера записей, отдельным
блоком — что не распозналось никем, кроме `llm_fallback`. `--dry-run` прогоняет разбор
целиком, но ничего не пишет в БД.

Та же функция стоит за существующей ручкой `/api/kb/ingest/preview` — админка получает
предпросмотр без дублирования логики.

### 6. Разбор `services/ingest.py` на модули

728 строк → шесть файлов с одной ответственностью каждый:

```
app/ingest/
    records.py      — датаклассы записей и провенанс
    registry.py     — реестр источников, выбор по sniff
    blob.py         — FileBlob: кодировка, ленивый текст и таблицы
    chunking.py     — split_sections, _merge_tiny, _is_junk        (из ingest.py)
    questions.py    — generate_question, fallback_question, keywords (из ingest.py)
    figures.py      — figure_numbers, attach_images, strip_dangling  (из ingest.py)
    assets.py       — сохранение картинок, три способа привязки
    pipeline.py     — записи → БД, прогресс, blue/green переиндексация
    sources/*.py    — источники
```

`app/services/ingest.py` остаётся тонким фасадом: реэкспорт публичных имён, чтобы
`routers/kb.py`, `tasks/jobs.py` и 26 файлов тестов не переписывались.

### 7. Конвейер `ChatService` (второй день)

`handle_user_message` → явная последовательность шагов над общим объектом хода:

```
guardrails → раскладка → роль → поиск → дословный ответ → уточнение → агент → эскалация → постобработка
```

Каждый шаг — файл в `app/chat/steps/`, сигнатура `async def run(turn: Turn) -> StepResult`
(`continue` | `answered` | `stop`). `ChatService` остаётся владельцем сессии и сокетов,
но перестаёт быть местом, где живёт вся логика. Поведение не меняется — это чистый
перенос под прикрытием тестов.

## Совместимость

- Публичные имена `app.services.ingest` сохраняются фасадом.
- `KBArticle.origin` добавляется как nullable JSON — досинхронизация схемы на живом
  стенде так же, как делалось для `audience`.
- Ответ API получает необязательное поле `verbatim: bool` в мета сообщения; старые
  клиенты его игнорируют.

## Тесты

- Существующие 296 тестов — критерий того, что перенос ничего не сломал: гоняются после
  каждого шага разбора.
- Новое покрытие: по одному тесту на источник (минимальный файл каждого формата в
  `tests/fixtures/`), тест на распознавание колонок по содержимому, тест на
  ответ-картинку, тест на дословный ответ (включается и отключается тумблером), тест
  реестра (выбор по уверенности и падение к следующему источнику).
- Регресс качества (`golden.json`) прогоняется до и после — метрики не должны просесть.

## Порядок и риски

| День | Что |
|---|---|
| Ср | Записи, реестр, разбор `ingest.py`, источники `qa_table`/`document`/`pdf_figures`, разведчик |
| Ср вечер | `spreadsheet`, `json_records`, `image_folder`, `llm_fallback` |
| Чт | Картинки-ответы, дословный ответ, тумблеры в админку |
| Чт вечер | Конвейер `ChatService` |

Риск один: разбор большого файла ломает работающую систему за день до старта. Снимается
порядком работ — фасад сохраняет импорты, тесты гоняются после каждого шага, и если
время кончится на конвейере `ChatService`, система остаётся рабочей и полной.
