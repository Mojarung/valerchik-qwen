# Приём данных: что делать, когда выдали архив

Короткая инструкция на день выдачи данных. Код — в `backend/app/ingest/`.

## Что происходит с файлом

```
файл → FileBlob → реестр источников → записи → конвейер → база
                  (кто возьмётся?)     (что это?)  (куда класть?)
```

Источник знает, как читать свой формат, и ничего не знает про базу. Конвейер знает
про базу и ничего не знает про форматы. Поэтому новый формат = новый файл в
`app/ingest/sources/`, и чужой код при этом не трогается.

## Первое действие: разведка

```powershell
uv run python -m app.tools.recon C:\путь\к\выданным\данным
uv run python -m app.tools.recon данные.zip --json    # машиночитаемо
uv run python -m app.tools.recon данные --limit 20    # только первые 20 файлов
```

Отчёт показывает по каждому файлу: кто из источников берётся и с какой уверенностью,
сколько записей выйдет, три примера и — отдельным блоком внизу — что не разобрал
никто. Этот блок и есть список форматов, под которые нужен новый источник.

Разведка ничего не пишет в базу и не требует поднятого стенда.

## Источники сейчас

| Источник | Берёт | Уверенность |
|---|---|---|
| `pdf_figures` | PDF при поднятом профиле `docs`: текст + иллюстрации с подписями | 0.85 |
| `support_export` | Выгрузку службы поддержки (лист с колонками «Тема», «Описание», «Решение»): строки складываются по ответу оператора, статья — ответ, данный хотя бы дважды; вопрос — реальное обращение, префикс «Подтема запроса:» уходит в ключевые слова | 0.97 |
| `spreadsheet` | Книгу Excel полистно: лист «вопросы», лист «отзывы», остальное пропускает | 0.90 |
| `json_records` | JSON/JSONL, массив объектов ищется и в глубине (`{"data": {"faq": [...]}}`) | 0.90 |
| `qa_table` | Готовую выгрузку «вопрос — ответ»: markdown-таблица, CSV с `;`, `,` или табуляцией | 0.60–0.95 |
| `image_folder` | Картинку: вопрос берётся из имени файла, ответ — сама картинка | 0.80 |
| `document` | Любой текст: методичка режется по заголовкам, вопрос формулирует LLM | 0.45 |
| `llm_fallback` | Всё остальное: модель размечает файл сама | 0.16 |

Выигрывает самый уверенный. Если он отказался (`SourceMismatch`) или не дал ни одной
записи — очередь идёт к следующему.

## Что берётся из самих данных

Три поля источник обязан пытаться прочитать в файле, а не принимать снаружи:

- **вопрос и ответ** — колонки распознаются по имени, а если имя незнакомое, по
  содержимому (колонка, где ячейки кончаются «?», — вопрос);
- **линия поддержки** — колонка «Линия» / «Line» / «Уровень», значения «2», «Л2» и
  «вторая линия». Значение из формы загрузки остаётся умолчанием на весь документ,
  колонка — правдой про конкретную строку: частное сильнее общего;
- **`authored`** — писал ли текст человек. От него зависит дословный ответ.

Категория и роль (поставщик/заказчик) приезжают снаружи: в выгрузках их обычно нет.

## Виды записей

- `ArticleRecord` → `kb_articles`. Поле `origin.authored` решает судьбу **дословного
  ответа**: текст, написанный человеком, уходит пользователю слово в слово; текст,
  который мы сами нарезали, — через агента.
- `FeedbackRecord` → `feedback`. Имя специалиста сопоставляется с пользователем,
  незнакомое заводится неактивным — иначе рейтинг специалистов считать не по кому.
- `DialogRecord` → `chat_sessions` + `messages`, каналом `import`: чужая выгрузка не
  должна подменять собой статистику стенда.
- `AssetRecord` → хранилище картинок, привязка к статье в `app/ingest/assets.py`.

## Новый источник за пятнадцать минут

1. Скопировать шаблон в `app/ingest/sources/<имя>.py`:

```python
"""Одна строка: что это за формат и почему он разбирается именно так."""

from __future__ import annotations

from collections.abc import AsyncIterator

from app.ingest.blob import FileBlob
from app.ingest.records import ArticleRecord, Provenance
from app.ingest.registry import IngestContext, register


@register
class МойИсточник:
    name = "my_source"
    priority = 20          # выше 0 — специализированный, отрицательный — запасной

    async def sniff(self, blob: FileBlob) -> float:
        """0..1. Ниже 0.15 значит «не берусь»."""
        if blob.suffix != ".xml":
            return 0.0
        return 0.9 if b"<faq" in blob.data[:2048] else 0.0

    async def parse(self, blob: FileBlob, ctx: IngestContext) -> AsyncIterator[ArticleRecord]:
        for index, (question, answer) in enumerate(разобрать(blob.decoded()), start=1):
            yield ArticleRecord(
                question=question,
                answer=answer,
                category=ctx.params.get("category", ""),
                line=ctx.params.get("line"),
                audience=ctx.params.get("audience", "all"),
                origin=Provenance(file=blob.name, locator=f"запись {index}",
                                  source_name=self.name,
                                  # True только если текст написал человек!
                                  authored=True),
            )
```

2. Рядом `tests/test_source_<имя>.py` с минимальным файлом этого формата.
   Фикстуру `client` не подключать — она поднимает всё приложение и медленная.
3. `uv run pytest tests/test_source_<имя>.py -q` и `uv run ruff check .`.

Регистрировать нигде не нужно: `sources/__init__.py` находит модули сам.

## Про `authored`

Единственное поле, которое стоит проверить дважды. `authored=True` означает «ответ
написан человеком и его можно отдать пользователю без изменений». Ставить его на
куски, нарезанные нами из методички, нельзя: они писались как абзац инструкции, а не
как ответ на вопрос, и дословная выдача выглядела бы обрывком.

Дословный путь включается тремя условиями сразу (`app/services/verbatim.py`):
статья `authored`, оценка поиска выше `answer.verbatim_score`, совпадение вопросов
выше `answer.verbatim_similarity`. Все три правятся в админке на лету, тумблер —
`answer.verbatim_enabled`.

## Порядок действий в день выдачи

1. `recon` по всей папке — понять, что дали.
2. Форматы из блока «НЕ РАЗОБРАНО» — по источнику на каждый, параллельно разными людьми:
   файлы не пересекаются.
3. Загрузка через админку (`/admin/import`) или ручкой `POST /api/kb/ingest/file`.
   Расширение значения не имеет — формат определяет реестр.
4. Проверить дословные ответы на десятке вопросов прямо из выданного файла.
5. `uv run pytest -q` перед демонстрацией.
