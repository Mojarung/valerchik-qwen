# План реализации и архитектурные решения

Проект: интеллектуальная система автоматизации поддержки Портала поставщиков (zakupki.mos.ru).
Статус: все этапы ниже реализованы и проверены (тесты + живое демо), кроме раздела «Роадмап».

Состояние гейтов на текущий коммит: `ruff` (включая формат и `mypy`) чисто, **521 тест**, покрытие **88 %** при гейте 80 %,
`tsc --noEmit` чисто, `vite build` собирается, расширение проходит живую проверку на портале
(`extension/scripts/e2e.mjs`).

## 1. Соответствие задачам хакатона

| Задача ТЗ | Реализация |
|---|---|
| Изучить данные организаторов | Данных на руках нет; путь загрузки готов (строка ниже), переучивать при их появлении ничего не нужно. База наполнена синтетикой: 67 статей в 11 категориях по 3 линиям, с ролью «поставщик / заказчик / все». Плюс `scripts/portal_kb.py` забирает настоящую базу знаний портала (326 статей с ролями) в формат импорта |
| Структурировать базу знаний | Загрузка файлом: pdf, docx, xlsx, xls, pptx, html, md, txt. Документ режется по заголовкам и абзацам, к каждому фрагменту LLM формулирует вопрос, который он закрывает, линию подсказывает тот же классификатор, что маршрутизирует обращения. Готовая выгрузка «вопрос — ответ» таблицей распознаётся и идёт прямым импортом. Иллюстрации (профиль `docs`, docling) привязываются по авторской нумерации из текста. Импорт — фоновая задача с прогрессом |
| Автоконсультации по типовым вопросам | Гибридный RAG (BERTA + BM25 + RRF, опционально cross-encoder) → ReAct-агент → ответ с источниками и уверенностью |
| «Нет ответа → сообщить и предложить оператора» | Порог уверенности (настраиваемый): ниже — честный отказ + предложение оператора; вопрос фиксируется как «пробел БЗ» с подсчётом повторов. Отдельно: две близкие статьи из разных тем → уточняющий вопрос вместо ответа наугад |
| Распознавание нецензурной лексики + автозавершение | Детектор с нормализацией обфускаций (гомоглифы, разделители, побуквенно, латиница, `*`-цензура, невидимые символы, растянутые буквы, английская раскладка) → автозакрытие обращения с уведомлением; режим warn/close настраивается |
| Идентификация линий поддержки | Классификатор на эмбеддингах (softmax-регрессия, numpy), фолбэк на ключевые правила; дообучение на статьях + реальных эскалациях; hot-swap модели |
| Оценка специалистов + заключение | Отзывы (1–5 + комментарий) → сентимент → кластеризация негатива по эмбеддингам → рейтинг специалистов (ИИ — тоже специалист) → содержательное заключение (шаблон / LLM) |
| Удобный веб-интерфейс | React SPA: чат (live WS, стриминг, голос, чипсы, маскот), оператор (очередь, подсказки из БЗ, черновик ответа от ИИ, поиск, шаблоны), админка (БЗ, импорт, настройки, статистика, отзывы, пробелы, регресс качества, MCP). Адаптив проверен на 14 экранах при 390 и 320 px. Плюс виджет `embed.js` для встройки на сторонний сайт одной строкой |
| Тестирование на реальных кейсах | 521 автотест, покрытие 88 % при гейте 80 %. Отдельно — золотой набор из 60 перефразированных вопросов с эталонами: прогон по кнопке в `/admin/quality`, метрики рядом с прошлым прогоном, доля уверенных ошибок считается отдельно от доли ненайденных |
| Масштабирование | stateless API ×N за nginx, Redis pub/sub для WS и конфигов, воркеры taskiq, blue/green переиндексация |
| Демонстрация | `start.ps1` / `docker compose up` — весь стек одной командой; lite-режим — вообще без Docker |
| BPMN-схема | Три процесса в нотации BPMN 2.0 — обращение, структурирование БЗ, оценка качества: [docs/BPMN.md](docs/BPMN.md). Валидный XML с координатами (открывается в Camunda Modeler / bpmn.io) + SVG для презентации, генерируются из общего описания скриптом `scripts/bpmn.py` |

Сверх ТЗ: поиск товаров каталога портала (СТЕ, цены, фотографии) через собственный MCP-сервер —
карточки листаются каруселью прямо в чате; роль собеседника «поставщик / заказчик» на всём пути
от поиска до промпта; расширение для браузера, которое ведёт по zakupki.mos.ru по шагам.

## 2. Ключевые решения и обоснования

**Python 3.14 + uv.** Все зависимости проверены на cp314 (ресёрч по PyPI, август 2026).
uv везде — локально, в CI и в Docker (`ghcr.io/astral-sh/uv:python3.14-bookworm-slim`, `uv.lock`).

**Docker Compose, а не Kubernetes.** Для хакатона и пилота нужен подъём одной командой на любой
машине. Compose даёт: профили (`voice` / `rerank` / `docs` / `s3`), healthchecks, `--scale api=N`.
Все сервисы stateless (кроме БД) — миграция на k8s при необходимости сводится к манифестам,
архитектуру менять не нужно.

**GitHub Actions, а не Jenkins.** Jenkins требует отдельный сервер, плагины и обслуживание — для
команды хакатона это чистые накладные расходы. Actions живёт рядом с кодом, бесплатен для
репозитория, поднимает Python/Node/Docker из коробки. Вывод: **Jenkins не нужен**; если у
организаторов корпоративный Jenkins — пайплайн переносится 1:1 (этапы: lint → test → build → push).

**pydantic-ai (v2) как каркас ReAct-агента.** Актуальный фреймворк 2026 года от команды Pydantic:
типизированные инструменты, кастомный OpenAI-совместимый `base_url` (подходит любой провайдер —
Ollama, OpenRouter, GigaChat-прокси), `FunctionModel` для детерминированного офлайн-режима.
Тот же цикл reason → search_kb → observe → answer/refuse/escalate работает и без LLM (mock),
и с реальной моделью — проверено на `qwen3.8:27b` через Ollama.

**Эмбеддинги: sergeyzh/BERTA через TEI.** По ruMTEB-2026 BERTA даёт ~98% качества FRIDA при
размере 0.1B и совместима с text-embeddings-inference (Rust-сервер, CPU-образ, без Python-зависимостей).
FRIDA лучше, но FRED-T5-архитектура не поддерживается TEI. Реранкер — `BAAI/bge-reranker-v2-m3`
вторым TEI-контейнером (профиль `rerank`, выключен по умолчанию ради скорости CPU).

**Гибридный поиск.** Векторный (Qdrant, cosine, 768-мерная BERTA) + лексический BM25 (in-memory,
idf-взвешенный overlap как мера уверенности) → слияние Reciprocal Rank Fusion. Стоп-слова вежливости
(«здравствуйте, подскажите…») отфильтрованы. Уверенность = max(vec, kw) при семантическом эмбеддере;
в lite-режиме хэш-эмбеддер помечен `semantic=False` и уверенность строится на BM25.
RRF определяет *состав* выдачи, показывается она по убыванию уверенности — иначе проценты
у источников идут вразнобой.

**Cross-encoder реранкер** (профиль `rerank`, `DiTy/cross-encoder-russian-msmarco` через TEI).
Замер на 6 сложных разговорных запросах: попаданий в топ-1 **2/6 → 4/6**, задержка поиска
38 мс → 446 мс (на фоне 2–4 с ответа LLM незаметно). Включается автоматически, если задан
`TEI_RERANK_URL`, и переключается тумблером `retrieval.use_reranker` без перезапуска.

**Контекст страницы вместо догадок.** Виджет передаёт раздел портала, с которого задан вопрос:
«как отменить» со страницы оферт и из карточки сессии — разные вопросы, и раздел участвует в
ранжировании. Query-строка не передаётся никогда: портал кладёт туда номера заявок и ИНН.
Фрейм и страница-хозяин обмениваются рукопожатием (`ready` → `page`), потому что виджет приезжает
ленивым чанком и `postMessage` по событию `load` уходил раньше, чем появлялся слушатель.

**Роль собеседника — сквозная, а не фильтр в интерфейсе.** База знаний портала и сама разделена на
разделы для поставщиков, для заказчиков и общий, и на «как зарегистрироваться» у сторон разные
ответы (ЭП и заявка на регистрацию компании против уполномоченного органа региона и ЕАИСТ).
Поэтому роль — колонка статьи, фильтр кандидатов до слияния RRF (статья другой стороны не занимает
место в выдаче), строка в промпте агента и свои чипсы. Роль приходит тремя путями с приоритетом
слова собеседника > переключатель > память диалога: «я заказчик» написано только что, а
переключатель мог остаться от прошлого раза. Неизвестная роль — честное «all»: если две статьи для
разных сторон почти одинаковы по формулировке и стоят вплотную, бот спрашивает «вы поставщик или
заказчик?», а ответ на этот вопрос возвращает к исходному вопросу, а не ищет реплику «я заказчик».
Полоса срабатывания узкая: обе статьи адресные, формулировки совпадают на ≥50 % слов, оценки
близки — иначе это два разных вопроса, и роль в них ничего не решает.

**Расширение ведёт по порталу без VLM.** Распознавать экран моделью — секунды на шаг и внешний
вызов на каждый экран; вместо этого портал разобран заранее: 367 маршрутов с заголовками из бандла,
селекторы с живого DOM (у styled-components есть `displayName`, поэтому `[class*="TopMenuStyles__…"]`
стабилен), `data-testid` у кнопок шапки. Сценарии — список шагов с локаторами по убыванию
надёжности, подбираются к вопросу лексически с учётом роли и едут в `meta.guide` ответа. Движок в
расширении ищет элемент миллисекунды, вырезает его из затемнения, ставит карточку и «перебегает»
маскотом; переходы между страницами переживает через `sessionStorage`, а развилки портала (кнопка в
шапке ведёт сразу на форму регистрации, минуя форму входа) проходит, перескакивая к шагу, чья
страница уже открыта. Два открытия по дороге: Chrome 2026 блокирует фреймы на localhost с публичных
https-страниц (Local Network Access), а страницы входа шлют `frame-src 'self'` — поэтому чат грузится
через страницу самого расширения, которой эти запреты не касаются. Цена подхода — сценарии надо
обновлять при смене вёрстки портала; на это есть живой e2e-прогон.

**Каталог товаров отдельным MCP-сервером, а не модулем внутри API.** Две причины: инструменты
каталога нужны и внешним MCP-клиентам тоже, а хождение к чужому порталу с собственным лимитом
скорости и кэшем не должно делить процесс с ответами пользователям. Порт наружу не публикуется.
Цены показываются с обязательной пометкой, какая именно это цена (референтная, медианная или
цена предложения): «192 620 ₽» без пометки — дезинформация, за которой человек пойдёт в закупку.
Если портал не отдал ни одной цены, система не выдумывает.

**Товарный запрос опознаётся по вопросу, а не по молчанию базы знаний.** Подключение MCP стоит
секунд, поэтому оно не делается на каждое сообщение. Первая версия правила звучала как «база
знаний не ответила — значит нужен внешний источник»: на шестидесяти синтетических статьях это
работало, а после импорта методичек поиск стал возвращать что-нибудь с оценкой около 0.5 на любой
вопрос, порог перестал пробиваться, и каталог не подключался ни разу. Теперь намерение видно из
самой фразы («найди», «купить», «сколько стоит»), выражение правится из админки. По той же причине
уточняющий вопрос не задаётся на товарных запросах: у «найди машины до 1.5м» нет двусмысленности,
которую стоит выяснять у человека, — есть каталог, где надо посмотреть.

**Разбор PDF отдельным сервисом (профиль `docs`).** docling тянет torch: это пара гигабайт образа,
которые не нужны для работы чата. Отдельный контейнер под профилем означает, что базовый стек
остаётся лёгким, а разбор иллюстраций включается только когда он нужен. torch ставится из
CPU-индекса явно — иначе uv приносит сборку с CUDA.

**Голос локально, а не через облако.** STT (faster-whisper, int8) и TTS (Piper на onnxruntime) —
свои контейнеры под профилем `voice`. Единственный внешний вызов в системе остаётся один — LLM.
Перед озвучкой с текста снимается Markdown: «звёздочка звёздочка срок звёздочка звёздочка»
справкой не является.

**Lite-режим как первоклассный гражданин.** Каждый адаптер (кэш, векторка, эмбеддер, LLM, брокер)
имеет in-memory реализацию: SQLite + fakeredis + numpy + FunctionModel + InMemoryBroker.
Это даёт: демо без интернета и Docker, быстрые честные тесты (та же оркестрация, что в проде),
CI без сервисов-контейнеров.

**Динамика без рестартов.** Три механизма:
1. Настройки: БД → in-memory кэш инстанса → Redis pub/sub `cfg:changed` (промпт, пороги, лимиты,
   guardrails-списки, LLM-провайдер — всё меняется из админки на лету).
2. База знаний: правка → переиндексация → pub/sub `kb:changed`; полная переиндексация — blue/green
   через алиас Qdrant `kb_current` (поиск не прерывается).
3. Классификатор: артефакт на диске + версия в Redis → инстансы горячо подменяют модель.

**Классификатор линий без sklearn.** Softmax-регрессия на numpy (~60 строк): нулевой риск
несовместимости колёс, мгновенное обучение на сотнях примеров, полный контроль версионирования.
На бо́льших данных заменяется на sklearn/каскад без изменения интерфейса `LineClassifier`.

**Темы вместо частотности по тексту.** Вопросы группируются по эмбеддингам: одна проблема в трёх
формулировках — одна тема, а не три редких вопроса. То же решение и в кластеризации негативных
отзывов: иначе заключение о системных проблемах распадается на список единичных жалоб.

**Качество меряется на золотом наборе, а не на глаз.** 60 перефразированных вопросов с эталонными
статьями, прогон по кнопке, метрики рядом с прошлым прогоном. Уверенные ошибки считаются отдельно
от ненайденных: первые опаснее — человек получает неверный ответ, а порог не срабатывает.

**Схемы BPMN генерируются кодом.** `scripts/bpmn.py`, только стандартная библиотека. Раскладка
описана декларативно сеткой «колонка × дорожка», координаты фигур и изломы стрелок считаются.
`.bpmn` и `.svg` собираются из ОДНОГО описания и не могут разойтись — картинка в презентации
всегда показывает ровно то, что лежит в исходнике схемы. CI перегенерирует схемы и падает,
если файлы правили руками.

**Резервные копии отдельным контейнером.** `pg_dump` обязан быть не старше сервера, и образ
postgres даёт эту гарантию даром. Расписание лежит в настройках админки, контейнер перечитывает
их раз в минуту — ни cron на хосте, ни планировщика Windows не требуется.

**Безопасность.** JWT (PBKDF2-пароли, roles user/operator/admin), rate limit по скользящему окну
(настраиваемый), маскирование ПДн в выгрузках, эвристики prompt-инъекций, секреты только в `.env`,
аудит-лог действий админа. LLM получает только контент диалога и статьи БЗ.

## 3. Этапы (все выполнены)

1. **Ресёрч (лето-2026)** — версии/совместимость py3.14 по PyPI JSON, выбор моделей для русского.
2. **Ядро бэкенда** — конфиг, БД, адаптеры ×2 реализации, guardrails, retrieval, агент, роутинг,
   аналитика, динамические настройки.
3. **API-слой** — REST + 2 WebSocket-канала, rate limit, метрики, SQLAdmin, фоновые задачи taskiq.
4. **Синтетические данные** — 67 статей БЗ в 11 категориях с ролями, 122 диалога (78 авторешённых с отзывами
   у 55 %, 20 эскалаций — каждая третья на «слабого оператора» op_sergey, чтобы в аналитике было
   видно расслоение специалистов, 6 нарушений, 18 вопросов вне БЗ), 6 пробелов БЗ;
   детерминированный сидер (seed=42). Сидит только пустую базу (`kb_count == 0`).
5. **Тесты** — 521 штука: юниты guardrails/поиска/классификатора/импорта/роли/сценариев + e2e через
   TestClient с полным жизненным циклом приложения; coverage-гейт 80 % (факт 87 %).
6. **Фронтенд** — React 19 + Vite 8 + Tailwind 4 + lucide + recharts + zustand + gsap; lazy-чанки
   (чат не грузит админку, recharts — отдельный чанк), адаптив 320–1920, анимированный SVG-маскот
   с 6 состояниями, карусель карточек товаров (стрелки, свайп, клавиатура, лайтбокс).
7. **Структурирование неформализованной БЗ** — импорт методичек файлом, нарезка по заголовкам,
   формулировка вопроса к фрагменту, распознавание готовых табличных выгрузок, отсев мусорных
   строк (номера страниц и подписи к рисункам вместо ответов), привязка иллюстраций по авторской
   нумерации, S3-совместимое хранилище картинок (профиль `s3`, MinIO).
8. **Каталог товаров** — свой MCP-сервер к порталу (поиск СТЕ, цены с пометкой вида, фотографии
   через собственный домен), карточки-карусель в чате, инструменты доступны и внешним агентам.
9. **Голос** — STT (faster-whisper) и TTS (Piper), оба локально, профиль `voice`.
10. **Виджет** — `embed.js` ~2 КБ без зависимостей: кнопка в углу, ленивый iframe на `/widget`,
    микрофон во фрейме, передача контекста страницы-хозяина.
11. **Инфраструктура** — compose (14 сервисов, 4 профиля, healthchecks, `mem_limit` у api),
    Dockerfile'ы на uv, nginx с DNS-балансировкой для `--scale`, контейнер резервных копий.
12. **CI/CD** — Actions: CI на push/PR (backend lint+тесты с гейтом покрытия, каталог lint+тесты,

## 4. Демо-сценарий (5 минут)

Порядок собран так, чтобы жюри увидело все пункты задания подряд и не искало функциональность само.

1. `.\start.ps1` → открыть чат: чипсы, задать «Как зарегистрироваться на Портале поставщиков?» →
   стриминг ответа, источники с процентами, маскот «говорит».
2. Задать вопрос про несуществующее → честный отказ, маскот «извиняется» → в админке
   «Пробелы БЗ» появился вопрос → «Создать статью» → повторить вопрос → ответ есть (самообучение).
3. «Позовите оператора, не работает ЭЦП» → эскалация на линию 2 → вкладка оператора: тикет в
   очереди, взять, подсказки из БЗ и черновик ответа от ИИ, быстрые шаблоны, закрыть →
   пользователь ставит оценку.
4. Написать с матом → предупреждение системы, обращение закрыто автоматически.
5. Загрузить методичку в `/admin/import` → прогресс фоновой задачи → статьи появились в БЗ,
   у источника видны иллюстрации из инструкции.
6. «Покажи ноутбуки» → карточки товаров каталога портала с фотографиями и ценами (с пометкой,
   какая это цена), карусель листается стрелками и пальцем.
7. Админка → Настройки: поменять приветствие/порог → новый диалог сразу другой (без рестарта!).
   Вставить ключ LLM → агент отвечает генеративно (тот же чат, тот же код).
8. Админка → Отзывы: сформировать отчёт → рейтинг специалистов, кластеры проблем, заключение.
   Дашборд: графики за 14 дней, темы обращений и что выросло к прошлой неделе. Выгрузки CSV.
9. Админка → Регресс качества: прогнать золотой набор, метрики рядом с прошлым прогоном.
10. Открыть `/embed-test.html` — виджет на стороннем сайте, вопрос из фрейма, контекст страницы
    доезжает до ответа.
10a. Спросить «Как зарегистрироваться на портале?» без выбранной роли → бот переспрашивает
    «вы поставщик или заказчик?», ответ «Я заказчик» переводит ползунок и даёт инструкцию про
    уполномоченный орган; переключить ползунок на «Поставщик» → чипсы и ответы меняются.
10b. Загрузить `extension/` в Chrome, открыть zakupki.mos.ru, задать тот же вопрос → «Показать на
    портале»: Валерчик подсвечивает «Зарегистрироваться», карточка шага, клик — и на форме
    регистрации Keycloak он уже ждёт со следующим шагом.
11. Схема BPMN (`docs/bpmn/support.svg`) и `docker compose up -d --scale api=3` — масштабирование
    на глазах, WebSocket продолжает работать.

## 5. Риски и как они закрыты

| Риск | Митигация |
|---|---|
| LLM-API недоступен/дорог | Mock-режим на том же ReAct-цикле; порог уверенности отсекает галлюцинации; таймаут + деградация до отказа |
| Колёса под py3.14 | Ресёрч подтвердил все зависимости; тяжёлый ML вынесен в TEI (Rust) и отдельные контейнеры STT/TTS/docparse |
| Плохая базовая БЗ | Петля самообучения: пробелы → статьи; ответы операторов → черновики статей |
| Мусор в импортированных методичках | Отсев строк, где вместо ответа стоит номер страницы, подпись к рисунку или кусок самого вопроса — такая статья опаснее пустой: вопрос совпадает точно, уверенность высокая, до честного отказа дело не доходит |
| Ложные срабатывания детектора мата | Слова-исключения сравниваются по основе, а не по точной форме: «бляшкой» и «бляшка-имплант» больше не закрывают обращение, и администратору не нужно перечислять падежи руками. Плюс режим warn; списки правятся из админки на лету |
| Модель ответила, не заглянув в базу знаний | Порог применять не к чему, подтвердить ответ нечем — считается отказом наравне с низкой уверенностью. Иначе придуманный ответ уходит человеку с источниками и процентами |
| Падение поиска при переиндексации | Blue/green алиасы Qdrant; атомарная подмена in-memory индекса |
| Портал каталога недоступен или отвечает мусором | Свой лимит скорости и ретраи в MCP-сервере, отдельный процесс — отказ каталога не роняет ответы по базе знаний |
| Один инстанс не тянет | stateless API, `--scale api=N`, Redis-шина, отдельные воркеры |
| Схема в презентации разошлась с исходником | `.bpmn` и `.svg` из одного описания, расхождение ловится в CI |

## 6. Роадмап (после хакатона)

- RAGAS-подобные метрики качества ответов (faithfulness) + Logfire-трейсинг агента.
- Переход FRIDA/USER2 + GPU-инференс; миникаскад интентов перед RAG.
- Мультиканальность: Telegram-бот, e-mail-шлюз (архитектура каналов уже заложена полем `channel`).
- SSO/ЕСИА для пользователей, RBAC-матрица тоньше.
- Сортировка и фильтрация выдачи каталога: на коротких запросах портал подмешивает подстрочные
  совпадения («покажи машины» → «Программа обучения Машинист…»).
