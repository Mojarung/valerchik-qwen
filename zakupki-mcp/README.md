# MCP-сервер «Каталог Портала поставщиков»

Даёт агенту поиск по каталогу товаров zakupki.mos.ru (4.18 млн карточек СТЕ) вместе с
фотографиями. Подключается к «Валерчику» через реестр MCP в админке и поднимается вместе
со стеком — отдельной настройки не требует.

## Тулы

| Тул | Что делает |
|---|---|
| `search_products(query, limit, sort, only_with_offers, moscow_only, category_id)` | поиск товаров: название, цена, единица, категория, картинка, ссылка |
| `get_product(sku_id)` | полная карточка: характеристики, все цены, галерея |
| `product_images(sku_id, size)` | все картинки товара — превью нужного размера и оригиналы |
| `suggest_products(prefix, limit)` | быстрые подсказки по началу фразы |
| `catalog_status()` | доступен ли портал и на чём отвечаем — на нём или на кэше |

Тул, вернувший ключ `products`, показывается пользователю карточками с картинками —
это соглашение бэкенда (`app/services/agent.py`), а не особенность MCP.

## Откуда данные

Официального API у портала нет, поэтому используется внутренний — тот, которым ходит
сам сайт. Адреса корней портал публикует сам, в `GET /newapi/api/Js/GetJsSettings`:

```
webApiUrl        = https://zakupki.mos.ru/newapi       поиск, подсказки, файлы
classifierApiUrl = https://zakupki.mos.ru/classifier   карточка товара
```

Ключевые запросы (все — GET, все — без авторизации и кук):

```bash
# поиск: сложный фильтр едет одной JSON-строкой в query-параметре
curl -sG 'https://zakupki.mos.ru/newapi/api/Sku/QueryIndex' --compressed \
  --data-urlencode 'queryFilter={"take":5,"skip":0,"withCount":true,"filter":{"keyword":"ноутбук"}}'

# карточка
curl -s 'https://zakupki.mos.ru/classifier/api/Sku/GetSku?id=47387580'

# превью и оригинал картинки (fileStorageId = skuImageId из выдачи)
curl -s -o thumb.jpg 'https://zakupki.mos.ru/newapi/api/Core/Thumbnail/281054948/300/300'
curl -s -o full.jpg  'https://zakupki.mos.ru/newapi/api/FileStorage/Download?id=281054948'
```

### Кириллица ломается молча

Правильный UTF-8 портал понимает. Но если кодировка по дороге испортилась, он **не
сообщит об этом**: ответ 200, а выдача не по делу — на «ноутбук» приедут «Смартфон
OPPO F3» и «Zalman ZM-F3», потому что индекс токенизирует куски процентной записи
(`f3`, `e8`, `ee`). Легко потерять час, решив, что дело в неверном ключе фильтра.

Портить кодировку умеет не только чужой код: `curl --data-urlencode` в Git Bash на
Windows отдаёт строку уже перекодированной в CP1251 — ровно этот мусорный случай.

Поэтому клиент шлёт **ASCII-only JSON**: вместо самих букв в URL едут
последовательности `\u043d\u043e...`, и перекодировать по дороге нечего — ни шеллу,
ни прокси, ни чужой библиотеке. В Python это поведение `json.dumps` по умолчанию:
достаточно **не** ставить `ensure_ascii=False`. Инвариант закреплён тестом
`test_cyrillic_is_escaped_to_ascii_in_the_url`.

Проверить себя можно по ответу: в `additionalInfo.rawPhrase` портал возвращает фразу
такой, какой он её увидел. Читаемое слово — доехало верно, `"%e1%f3%ec..."` — битая.

### Что в фильтре работает, а что нет

Незнакомый ключ фильтра портал **молча игнорирует** и отдаёт полную выдачу — то есть
несуществующий фильтр выглядит как работающий. Поэтому в клиенте только проверенные:

| ключ | смысл |
|---|---|
| `keyword` | полнотекстовый поиск, нечёткий |
| `productionDirectoryId: {values:[id]}` | категория |
| `productionDirectoryPaths: {values:[".1.72092567."]}` | ветка дерева категорий целиком |
| `ids: {values:[...]}` | конкретные товары |
| `hasOffers: true` | только то, что можно купить прямо сейчас |
| `isMoscowProduction` / `isInnovation` | московское / инновационное |

| `referencePrice: {start, end}` | диапазон референтной цены |
| `isExact` | точная фраза целиком |

Формы значений между полями не совпадают, и перепутать их легко: диапазон — это
`{start, end}`, список — `{values: [...]}`. Не та форма даёт либо тихое игнорирование,
либо 500 с телом `Object reference not set to an instance of an object.`

Не работают (проверено, ключи молча игнорируются): `referencePriceGreatEqual`,
`costPerUnit*`, `priceFrom`, `offersCountGreatEqual`, `okpdId`, `idIn`,
`productionDirectoryIds`, `productionDirectoryPath` (в единственном числе),
а также любая фильтрация по региону и по стране происхождения — `regionPaths`
формально распознаётся, но значение не влияет на выдачу.

Сортировка: `order: [{"field": "relevance"|"referencePrice"|"createdDate"|"offersCount", "desc": bool}]`.
**Задавать явно**: без `order` выдача идёт не по релевантности (на «бумага» первым
приезжает «Диспенсер для туалетной бумаги»). Невалидное имя поля — 500.

Ещё две особенности, которые стоит знать, прежде чем строить на этом что-то большее:

* **`count` завышен** относительно того, что реально вычерпывается. На `isExact`-запросе
  портал отвечает `count=11` и отдаёт одну карточку. Показывать `count` пользователю как
  точное «найдено N» нельзя — это оценка.
* **Порядок выдачи между одинаковыми запросами слегка плавает**: топ стабилен, хвост
  страницы меняется. Постраничный обход через `skip` может пропустить и продублировать
  карточку, так что полное вычерпывание категории требует дедупликации по `id`.
* `take` формально до 1000, но `take=1000` на «ноутбуке» — это 119 МБ и четыре минуты.
  Наш потолок — 20.

## Как здесь принято ходить

Портал не ограничивает нас ничем: нет обязательных заголовков, нет кук, нет rate limit
(20 запросов подряд и 6 параллельных прошли без единого замечания). Ограничения ниже —
наша собственная дисциплина, а не их требование:

* **gzip обязателен.** На `take=50` это 860 КБ против 59 КБ — 93% трафика, который мы
  чужому сервису просто не создаём. httpx делает это сам.
* **Одно соединение на процесс.** Повторный запрос по живому keep-alive — 0.28с против
  0.51с холодного: экономится TLS-хендшейк.
* **`take` 5–20.** Позиция каталога весит ~17 КБ в разжатом виде (в основном
  характеристики), `take=1000` — это 109 МБ JSON и 5 секунд.
* **Свой лимит 2 запроса в секунду** (`ZAKUPKI_RPS`).
* **Кэш со stale-if-error**: поиск 15 минут, карточка сутки, а если портал упал —
  отдаём протухшее сколь угодно долго. Для поддержки вчерашняя цена — это ответ,
  а «сервис недоступен» — нет.
* **Таймауты 5с/30с.** Медиана ответа 0.5с, но примерно каждый двадцатый уходит в
  хвост на 9–10 секунд: с таймаутом в 10с мы бы рвали живые ответы и слали их заново.
* **500 у портала обычно означает наш кривой фильтр**, а не падение сервера — у такой
  ошибки узнаваемое тело, и повторять её незачем. 403 наоборот: наблюдался как
  разовая икота фильтра на всплеск, проходит с повтором.

`robots.txt` портала запрещает `/api` и `/admin`; используемые нами `/newapi`,
`/classifier` и `/sku/` под запрет не попадают.

## Запуск

```bash
uv run server.py          # 0.0.0.0:9200/mcp, транспорт streamable-http
uv run --group dev pytest # тесты (сеть не нужна)
```

| env | по умолчанию | зачем |
|---|---|---|
| `ZAKUPKI_MCP_HOST` / `ZAKUPKI_MCP_PORT` | `0.0.0.0` / `9200` | адрес прослушивания |
| `ZAKUPKI_RPS` | `2.0` | свой лимит запросов к порталу |
| `ZAKUPKI_THUMB_SIZE` | `300` | сторона бокса превью в пикселях |

В составе стека поднимается сам (`docker compose up -d`) и сам регистрируется в реестре
MCP при старте API. Наружу порт не публикуется: сервис доступен только внутри
compose-сети, по адресу `http://zakupki-mcp:9200/mcp`.

## Подключение к стороннему MCP-клиенту

```bash
claude mcp add zakupki-catalog --transport http http://localhost:9200/mcp
```

(для этого понадобится опубликовать порт — в `docker-compose.yml` добавить
`ports: ["9200:9200"]` сервису `zakupki-mcp`).
